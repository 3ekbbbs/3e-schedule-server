# 日程同步服务端

自托管的日程同步服务端。单个可执行文件，内置 SQLite、HTTPS 证书生成和可视化管理面板。不需要安装数据库、Web 服务器或 OpenSSL。

服务端只负责同步、分享和权限分发。日程内容保存在自己的机器上，不经过第三方。

## 功能

- 多端增量同步：全局序号、字段级合并、冲突记录、删除墓碑
- 账号体系：注册邀请码、管理员、封禁、批量建号、登录日志
- 共享与协作：日历成员、团队、邀请链接、实时笔记协作
- 内容审核：本地词库、举报处理、可选的大模型复核
- 客户端分发：版本更新、插件市场、设备列表
- 分发管理：安装包启停、版本说明、从别的站点克隆
- 多服务器联动：按内容路由下载请求，支持跳转与本地缓存两种模式
- 网络探测：自动识别公网与内网地址，生成可直接填入客户端的地址
- 对象存储：生成腾讯云 COS / CDN 的下载前缀
- 数据维护：孤儿扫描、重复日程清理、一致性备份、数据库恢复
- 管理面板：服务启停、配置、证书、账号、审核、分发、联动、日志

## 分发与联动

「分发」页管的是安装包发布之后的四件事：发不发、说明怎么写、要不要删、从哪儿复制一份。

**安装包状态**：每个平台一条记录。可以单独停用某个平台的更新 —— 文件还在磁盘上，只是客户端查不到、也下不到。恢复不需要重新上传。

**从别的站点克隆**：填一个源站地址，服务端自己去拉安装包。认两种源站：

| 源站 | 接口 | 说明 |
|---|---|---|
| 官网 | `/api/downloads` | 别人搭的下载页 |
| 另一台本程序 | `/api/updates/public` | 只填根地址即可 |

克隆时会核对源站给的 sha256。对不上直接失败，不会把半截文件写进分发记录。

克隆另一台本程序时，要填对方的令牌（部署令牌或管理员令牌）。对方用自签证书的话，还要勾「跳过证书校验」。

**多服务器联动**：可以加多台对端，然后按内容配路由。

| 模式 | 行为 | 适用 |
|---|---|---|
| 直接跳转 | 302 到对端，本机不经过文件 | 对端公网可达，想省本机带宽 |
| 缓存到本机 | 先从对端拉一份存下来再发 | 对端在局域网，或链路很慢 |

缓存命中之后即使对端离线也能继续供货。缓存目录是 `data/mirror/`。

路由配错了不会导致下载失败：规则不通就回退到本机文件。

**账号不参与联动**。账号永远只属于一台服务器，快照里也不包含账号、密码和令牌。

**配置快照**：导出成 JSON，另一台导入。搬运的是对端清单、路由规则和版本元数据。版本号不会覆盖本机记录，因为对方磁盘上的文件本机没有。

## 网络地址

概览页第一块是「客户端连这里」，列出这台机器能用的三条地址，每条都能一键复制。填进客户端的「服务器地址」就可以连上来。

- 公网地址：从外部服务探测，用于别人连你
- 内网地址：本机网卡上的私有地址，用于同一个局域网里的设备
- 本机地址：`127.0.0.1`

链路本地地址（`169.254.x.x`）会被排除，它们连不到任何地方。

探测公网地址意味着这台机器的出口 IP 会被第三方服务看到。探测失败时会如实显示原因，不影响服务本身。

## 数据放在哪

程序和数据分开。新装时数据写在程序目录之外：

| 平台 | 位置 |
|---|---|
| Windows | `%ProgramData%\3e-schedule-server\data`；没有这个变量时用 `%LOCALAPPDATA%` |
| Linux / macOS | `$XDG_DATA_HOME/3e-schedule-server/data`；没有就用 `~/.local/share/3e-schedule-server/data` |

证书在同一个根目录下的 `certs/`。

`data_dir` / `cert_dir` 留空就是这个行为。填了路径就按填的来，相对路径以 exe 所在目录为基准。

旧版本装在程序目录里的（`data/schedule.db` 就在 exe 旁边），升级后仍然读那一份，不会自己搬家。概览页会提示，点「搬到 …」把它复制到上面那个位置，原目录保留。

环境变量 `SCHEDULE_SERVER_ROOT` 可以改这个根目录。一台机器上跑多个实例时用它分开。


## 运行环境

| 平台 | 说明 |
|---|---|
| Windows x64 | 直接运行 exe |
| Linux x64 / arm64 | 单个二进制 |
| macOS | 单个二进制 |

程序静态编译，客户机不需要 Go、SQLite 或任何运行库。SQLite 与 IANA 时区数据库已编译进去。

## 快速开始（Windows）

1. 把 `schedule-server.exe` 放进任意目录。数据不写在这里，放哪都行。
2. 双击运行。程序会启动服务核心，并打开管理面板。
3. 浏览器地址是 `http://127.0.0.1:9800`。第一次打开时按提示创建管理员账号。
4. 概览页第一块列出这台机器的公网与内网地址，复制一条填进客户端的「服务器地址」。

首次启动会自动生成一张本地 CA 和一张服务端证书，放在数据根目录的 `certs/` 下：

```
certs/ca.crt        导入客户端设备，用于信任自签证书
certs/server.crt    服务端证书
certs/server.key    服务端私钥（权限 0600）
```

如果客户端不校验自签证书，可以跳过导入。生产环境建议在面板里上传正式证书。

## 更新

停掉服务，换掉 `schedule-server.exe` 就行。`data/`、`certs/`、`config.json` 不用动。

数据在程序目录之外，所以整个程序目录删掉重装也没有影响 —— 新 exe 启动时去同一个位置找数据。

## 命令行

```
schedule-server.exe                  启动管理器与管理面板
schedule-server.exe -run-server      只启动服务核心（由面板调用）
schedule-server.exe -init            写入默认配置后退出
schedule-server.exe -version         打印版本
schedule-server.exe -no-browser      启动时不打开浏览器
schedule-server.exe -config <路径>   指定配置文件
schedule-server.exe -import-db <db>  把旧版本的数据迁进来（备份后替换，做完退出）
```

图形界面版本没有控制台窗口，日志写在 `data/logs/` 下：

```
data/logs/server.log    服务核心日志
data/logs/manager.log   管理器日志
data/logs/console.log   子进程的标准输出
```

## 配置文件

默认路径是 exe 同目录的 `config.json`。面板里的修改会写回这个文件。相对路径以 exe 所在目录为基准，不是当前工作目录。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `addr` | `:8443` | HTTPS 监听地址，留空关闭 |
| `http_addr` | 空 | 额外的明文 HTTP 监听，适合放在反向代理后面 |
| `wordbook_addr` | 空 | 背词同步通道，留空关闭 |
| `internal_addr` | `127.0.0.1:0` | 面板调用的内部回环地址，`0` 表示随机端口 |
| `data_dir` | 空 | 数据库、日志、备份。空 = 程序目录之外，见「数据放在哪」 |
| `cert_dir` | 空 | 证书目录。空 = 和数据同一个根目录 |
| `server_name` | 空 | 生成证书时签入的域名 |
| `auto_cert` | `true` | 证书缺失时自动生成自签证书 |
| `invite_code` | 空 | 注册邀请码，空则首次启动自动生成 |
| `weather_place` / `weather_lat` / `weather_lon` | 北京市 | 下发给客户端的默认天气地点 |
| `live_secret` | 空 | 实时协作签名密钥，空则自动生成并落库 |
| `cos_base` | 空 | 更新包的对象存储前缀，空则从本机下载 |
| `market_url` | 空 | 网页版插件市场地址，空则客户端隐藏入口 |
| `panel_listen` | `127.0.0.1:9800` | 管理面板监听地址 |
| `panel_auto_open` | `true` | 启动时打开浏览器 |
| `auto_restart` | `true` | 服务核心异常退出时自动拉起 |

`diag` 打开 pprof，只在排障时使用。

## 管理面板

面板和服务核心是两个进程，所以停止服务不会把自己一起停掉。

| 页面 | 内容 |
|---|---|
| 概览 | 客户端连接地址、运行状态、账号/日历/日程数量、快捷操作、最近日志 |
| 服务 | 启动/停止/重启、地址探测、监听与目录、证书生成与上传、日志 |
| 账号 | 搜索、详情、封禁、管理员、删除、批量创建、邀请码 |
| 内容审核 | 违禁词增删改、待处理举报、AI 复核配置与测试 |
| 分发 | 安装包状态与克隆、插件审核、设备列表、联动服务器与路由 |
| 维护 | 备份、下载、从旧版本迁移、孤儿扫描、重复清理、登录日志、系统信息 |
| 插件 | 安装 / 停用 / 卸载、上传 zip；导航标注台与外观标注台 |
| 设置 | 天气、对象存储模板、插件市场、实时协作、部署令牌 |

账号列表里的「详情」会展开这个人的日历、日程、设备和最近登录。它回答的是「删掉这个账号会连带删掉什么」。

面板默认只监听 `127.0.0.1`。需要远程管理时，推荐用 SSH 隧道：

```bash
ssh -L 9800:127.0.0.1:9800 user@your-server
```

也可以把 `panel_listen` 改成 `0.0.0.0:9800`，但必须同时在防火墙里限制来源地址。

## 插件

标注台这类只有一部分人用得上的界面，不装在主程序里，而是作为面板插件存在。

```
data/panel-plugins/
  state.json              启用状态
  navstudio/
    manifest.json
    index.html
    ...
```

`manifest.json` 的最小形状：

```json
{
  "id": "navstudio",
  "name": "导航标注台",
  "version": "1.0.0",
  "entry": "index.html",
  "api": true
}
```

- `id` 决定目录名与访问路径 `/plugin/<id>/`，只允许小写字母、数字、连字符。
- 插件页面里以 `/plugin/<id>/api/...` 开头的请求由面板转发给服务核心，并换成当前会话的管理员令牌。
- 随程序附带 `navstudio`（导航标注台）与 `skinstudio`（外观标注台）。点「安装」才展开到数据目录，卸载会真的把目录删掉。
- 插件跑在面板的源上，权限等同于面板本身。只装你信任的来源。

装好的插件出现在侧边栏的「插件」组里。停用之后页面和接口都返回 403，直连地址也不行。

两个标注台都带一个「数据包」页：列出现有的 navpack / skinpack，可以复制授权码、删除、上传。导航包标完点「一键发布」，用户在客户端输授权码就能整份替换本机楼栋表。

### 重新构建插件包

标注台的源在网页端的 `public/` 目录里。改了那边之后：

```bash
node scripts/build-panel-plugins.mjs --from <网页端 public 目录>
```

脚本复制文件、把根路径 `/api/...` 与 `/nav-osm/...` 改写成插件前缀、断言没有漏网的，产物写到 `internal/panel/builtin/plugins/`，并打一份 zip 到 `dist/plugins/`（可以直接在面板里上传安装）。

⚠️ 不要用「把 `'/api/` 全文替换」这种写法：`nav-studio.js` 里有一处 `indexOf('/api/')` 是排掉腾讯地图 SDK 脚本的资源过滤器，改掉它地图不显示。脚本里那几条替换规则都写了预期命中数，源文件变了会直接报错停下。

## 从旧版本迁移

旧版服务端（单独一个 exe）和新版用的是同一份表结构，所以迁移在数据层面就是换库；新版启动时会补上新增的列和表。

### 步骤

1. 旧服务器上停掉服务。
2. 复制 `data/schedule.db`。同目录如果有 `schedule.db-wal` / `schedule.db-shm`，一起拿。
3. 新版面板 → 维护 → 备份与恢复 → 选文件 → **体检**。
4. 核对账号数、日程数、时间范围，对得上再点「确认迁移」。

体检只读上传上来的临时文件，不碰当前库。确认之后依次做这些事：

- 停服务
- 当前库复制到 `data/backups/pre-migrate-<时间>.db`
- 上传的库复制到 `data/backups/imported-<时间>.db`
- 替换 `data/schedule.db`，启动服务
- 重新数一遍，和导入源的账号/日程数量对账

迁移完成后旧登录令牌全部失效，需要用新数据里的管理员账号重新登录。这是故意的：换了库，旧 token 在新库里不存在。

### 命令行

```
schedule-server.exe -import-db "D:/old/data/schedule.db"
```

同一段逻辑，不经过 HTTP。适合没有浏览器的机器。

### 出问题怎么回去

面板 → 维护 → 备份，列表里会多出上面那两个文件。下载下来按同样步骤导回去即可，两份都是完整的 SQLite 库。

## 构建

需要 Go 1.23 或更高版本。`go.mod` 声明了 1.25，Go 会自动下载对应工具链。打发布包另外需要 Python 3（只用标准库里的 zipfile）。

打完整的发布包：

```bash
node scripts/package.mjs
```

产物：`build/schedule-server.exe`（编译结果）和 `dist/` 下两个 zip。脚本会先检查 `build/`、`dist/` 里有没有 `data/`、`certs/`、`config.json`，有就直接停下 —— 那是运行时的数据，不能当构建目录用。

只编译：

```text
scripts/build-windows.ps1      Windows
scripts/build-unix.sh          Linux / macOS
```

手动构建：

```bash
CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o build/schedule-server ./cmd/schedule-server
```

Windows 想隐藏控制台窗口，追加 `-H windowsgui`。

产物是静态二进制，可以直接复制到同架构的机器上运行。

## 目录结构

```
cmd/schedule-server/     入口：命令行、配置、管理器
internal/app/            服务核心：同步、账号、审核、分发、维护
internal/config/         配置结构与读写
internal/certgen/        自签 CA 与服务端证书生成
internal/panel/          管理面板后端与内嵌前端
  web/                   HTML / CSS / JS（无外部依赖）
  builtin/plugins/       随程序附带的面板插件（标注台）
scripts/                 构建脚本
```

运行时目录（默认在程序目录之外，见「数据放在哪」）：

```
data/schedule.db         主数据库（SQLite WAL）
data/live.db             实时协作数据库
data/backups/            VACUUM INTO 生成的备份
data/logs/               日志
data/updates/            客户端安装包与 manifest.json
data/mirror/             联动缓存（缓存模式下从对端拉下来的文件）
data/panel-plugins/      已安装的面板插件（每个插件一个目录）
data/invite.txt          邀请码
data/internal.addr       内部管理地址与令牌（0600）
```

## 备份与恢复

面板里的“生成备份”使用 SQLite 的 `VACUUM INTO`，服务运行中也能得到一致性快照。

恢复会停掉服务、替换数据库并重启。替换之前会留两份东西：

```
data/backups/pre-migrate-<时间>.db   换之前这台机器上的库
data/backups/imported-<时间>.db      这次传上来的那份
```

上传之后先做体检：文件头、必需的表、账号/日历/日程的数量、日程覆盖的时间范围。结构对不上的库直接拒绝，不会覆盖任何东西。

也可以直接复制 `data/schedule.db`，但要先停止服务，否则 WAL 里未落盘的部分会丢。

## 安全说明

- 第一个注册的账号自动成为管理员。部署完成后请立刻注册，不要留给别人。
- 密码使用 PBKDF2-HMAC-SHA256 存储，不保存原文。
- 管理面板的会话只存在内存里，重启管理器后需要重新登录。
- 自签证书的作用是让传输加密，不代表身份可信。客户端需要导入 `ca.crt`，或者换正式证书。
- 部署令牌保存在 exe 同目录的 `deploy-token.txt`，权限 0600。轮换后旧令牌立即失效。
- 服务端不保存客户端的大模型密钥。唯一例外是内容审核 AI 的密钥，它只用于服务端复核，接口返回时始终是掩码。

## 与客户端的协议兼容

插件清单的首选文件名是 `assets/schedule-plugin.json`（电脑端为包根 `schedule-plugin.json`）。历史包使用的 `assets/threees-plugin.json` 仍然兼容，不需要重新打包。

导航数据包与皮肤包的格式标识分别是 `schedule.navpack` 和 `schedule.skinpack`，旧标识同样兼容。
